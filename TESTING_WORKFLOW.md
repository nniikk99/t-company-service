## Сценарий тестирования

### Этап 1: Создание заявки оператором

1. Войдите в приложение как **operator@test.com**
2. Перейдите в раздел "Заявки"
3. Нажмите кнопку "Создать заявку"
4. Заполните форму:
   - Тип: Ремонт
   - Приоритет: Обычный
   - Оборудование: Выберите "Дизельный генератор Caterpillar C15"
   - Заголовок: "Не запускается генератор"
   - Описание: "При попытке запуска генератор не реагирует, индикаторы не горят"
5. Нажмите "Создать заявку"

**Ожидаемый результат:**
- ✅ Заявка создана успешно
- ✅ В базе данных в `service_requests` появилась запись с:
  - `user_id` = ID оператора
  - `supplier_id` = ID поставщика (автоматически из equipment)
  - `status` = 'pending' или 'approved'
  - `assigned_engineer_id` = NULL

**Проверка в SQL:**
```sql
SELECT 
    id,
    title,
    status,
    user_id,
    supplier_id,
    assigned_engineer_id,
    created_at
FROM service_requests
ORDER BY created_at DESC
LIMIT 1;
```

### Этап 2: Просмотр заявки поставщиком

1. Выйдите из аккаунта оператора
2. Войдите как **supplier@test.com**
3. Перейдите в раздел "Заявки"

**Ожидаемый результат:**
- ✅ Поставщик видит созданную заявку
- ✅ Отображается кнопка "Назначить инженера"
- ✅ Видна информация о заявке (заголовок, описание, статус)

### Этап 3: Назначение инженера поставщиком

1. Находясь в разделе "Заявки" под аккаунтом поставщика
2. Найдите созданную заявку
3. Нажмите кнопку "Назначить инженера"
4. В открывшемся диалоге должны отобразиться 2 инженера:
   - Петр Инженеров
   - Сергей Мастеров
5. Выберите "Петр Инженеров"
6. Нажмите "Назначить"

**Ожидаемый результат:**
- ✅ Появилось сообщение "Инженер Петр Инженеров назначен на заявку"
- ✅ Кнопка "Назначить инженера" исчезла
- ✅ В базе данных обновилась запись:
  - `assigned_engineer_id` = ID инженера
  - `status` = 'approved'

**Проверка в SQL:**
```sql
SELECT 
    sr.id,
    sr.title,
    sr.status,
    sr.assigned_engineer_id,
    up.first_name || ' ' || up.last_name as engineer_name
FROM service_requests sr
LEFT JOIN user_profiles up ON up.id = sr.assigned_engineer_id
ORDER BY sr.created_at DESC
LIMIT 1;
```

## Возможные проблемы и решения

### Проблема: Поставщик не видит заявки
**Решение:** Проверьте, что у оборудования заполнено поле `supplier_id`:
```sql
UPDATE equipment 
SET supplier_id = 'SUPPLIER_USER_ID'
WHERE id = 'EQUIPMENT_ID';
```

### Проблема: Инженеры не отображаются в списке
**Решение:** Проверьте, что у инженеров заполнено поле `supplier_id`:
```sql
UPDATE user_profiles 
SET supplier_id = 'SUPPLIER_USER_ID'
WHERE role = 'engineer' AND email IN ('engineer1@test.com', 'engineer2@test.com');
```

### Проблема: RLS блокирует доступ
**Решение:** Временно отключите RLS для отладки:
```sql
ALTER TABLE service_requests DISABLE ROW LEVEL SECURITY;
ALTER TABLE equipment DISABLE ROW LEVEL SECURITY;
-- После отладки обязательно включите обратно!
```
