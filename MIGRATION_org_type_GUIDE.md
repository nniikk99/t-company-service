# Миграция: Добавление org_type в компании

## Описание
Добавление поля `org_type` (тип организации) в таблицу `companies` с поддержкой трёх типов:
- **customer** (Заказчик) - компания, которая получает услуги
- **supplier** (Поставщик) - компания, которая продаёт товары
- **service_partner** (Сервисный партнер) - компания, которая оказывает услуги

## Порядок применения миграций

### Шаг 1: Применить основную миграцию
Откройте Supabase SQL Editor и выполните файл:
```sql
-- Файл: add_company_org_type.sql
```

Эта миграция:
- Добавляет столбец `org_type` в таблицу `companies`
- Создаёт индекс для фильтрации по типу
- Добавляет чек-констрейнт для валидации значений

### Шаг 2: Заполнить существующие компании
Выполните файл:
```sql
-- Файл: populate_org_type.sql
```

Эта миграция:
- Устанавливает `org_type = 'customer'` для всех существующих компаний
- Можно вручную изменить тип для конкретных компаний

**После выполнения** можно обновить типы конкретных компаний:
```sql
-- Пример: установить тип "Поставщик" для конкретной компании
UPDATE companies 
SET org_type = 'supplier' 
WHERE company_inn = '1234567890';
```

### Шаг 3: Обновить схему заявок и триггер
Выполните файл:
```sql
-- Файл: update_company_requests_schema.sql
```

Эта миграция:
- Добавляет поле `org_type` в таблицу `company_requests`
- Обновляет триггер `create_company_from_request()` для автоматического создания компаний с правильным типом

## Тестирование

После применения миграций протестируйте:

1. **Создание новой компании через регистрацию**
   - Зарегистрировать нового пользователя
   - Выбрать тип организации (Заказчик/Поставщик/Сервисный партнер)
   - Проверить что компания создалась с правильным `org_type`

2. **Добавление дополнительной компании**
   - Войти под существующим пользователем
   - Добавить новую компанию через диалог
   - Выбрать тип организации
   - Проверить что заявка содержит правильный `org_type`

3. **Отображение в списке клиентов**
   - Войти под админом
   - Открыть экран "Управление клиентами"
   - Проверить что для каждого пользователя отображается бейдж с типом его организации

4. **Проверка в базе данных**
   ```sql
   -- Посмотреть все компании с их типами
   SELECT id, name, company_inn, org_type 
   FROM companies 
   ORDER BY created_at DESC;
   
   -- Посмотреть заявки на создание компаний
   SELECT id, company_name, company_inn, org_type, status 
   FROM company_requests 
   ORDER BY created_at DESC;
   ```

## Rollback (откат изменений)

Если нужно откатить изменения:

```sql
BEGIN;

-- Удалить триггер и функцию (старые версии)
DROP TRIGGER IF EXISTS create_company_from_request_trigger ON company_requests;
DROP FUNCTION IF EXISTS create_company_from_request();

-- Удалить столбцы
ALTER TABLE company_requests DROP COLUMN IF EXISTS org_type;
ALTER TABLE companies DROP COLUMN IF EXISTS org_type;

-- Удалить индекс
DROP INDEX IF EXISTS idx_companies_org_type;

COMMIT;
```

## Дополнительные возможности (опционально)

### RLS политики на основе org_type
Если в будущем нужно будет разграничить доступ по типам организаций:

```sql
-- Пример: поставщики видят только свои компании
CREATE POLICY "Suppliers can view own company" ON companies
    FOR SELECT USING (
        org_type = 'supplier' AND id IN (
            SELECT company_id FROM user_profiles 
            WHERE id = auth.uid()
        )
    );
```

### Фильтрация компаний по типу в UI
В будущем можно добавить фильтры в списки компаний:
- Показывать только заказчиков
- Показывать только поставщиков
- Показывать только сервисных партнёров
