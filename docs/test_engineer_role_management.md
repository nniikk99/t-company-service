# 🧪 Инструкция по тестированию управления ролями инженеров

## Цель теста
Проверить, что ответственное лицо (companyResponsible) может назначать и изменять роли сотрудников своей компании, включая роль "Инженер".

## Предварительные условия
1. ✅ SQL миграция `add_supplier_role_and_marketplace.sql` выполнена
2. ✅ В базе данных есть:
   - Пользователь с ролью `companyResponsible` (Мария Петрова)
   - Сотрудники компании с ролями `siteManager`, `operatorPM`

## Шаги тестирования

### 1. Вход как Ответственное лицо
- **Пользователь**: Мария Петрова
- **Телефон**: +7 (999) 111-11-11
- **Пароль**: password
- **Роль**: Ответственное лицо компании

### 2. Переход в управление сотрудниками
1. После входа перейти в раздел "Управление сотрудниками"
2. Должен отобразиться список сотрудников компании
3. Проверить, что отображаются:
   - 🟢 Менеджеры площадок
   - 🔵 Операторы ПМ
   - 🟠 Инженеры (если есть)

### 3. Изменение роли сотрудника

#### Тест 1: Назначение роли "Инженер"
1. Найти сотрудника с ролью "Оператор ПМ" (например, Иван Сидоров)
2. Нажать на иконку 🔄 "Изменить роль"
3. В диалоге должны отображаться:
   - ✅ Текущая роль (с галочкой, неактивна)
   - Доступные роли:
     - 🟢 Менеджер площадки
     - 🔵 Оператор ПМ
     - 🟠 Инженер
4. Выбрать роль "Инженер"
5. **Ожидаемый результат**:
   - Диалог закрывается
   - Появляется уведомление "Роль [Имя] изменена на Инженер"
   - В списке сотрудников аватар стал оранжевым 🟠
   - Роль изменилась на "Инженер"

#### Тест 2: Изменение роли "Инженер" на "Менеджер площадки"
1. Найти сотрудника с ролью "Инженер"
2. Нажать на иконку 🔄 "Изменить роль"
3. Выбрать роль "Менеджер площадки"
4. **Ожидаемый результат**:
   - Аватар стал зеленым 🟢
   - Роль изменилась на "Менеджер площадки"
   - Появилась возможность назначать площадки

#### Тест 3: Проверка ограничений
1. Попробовать изменить роль на текущую
2. **Ожидаемый результат**:
   - Текущая роль неактивна (серая)
   - Нельзя выбрать

### 4. Проверка назначения площадок для инженера
1. Создать/найти сотрудника с ролью "Инженер"
2. Нажать кнопку "Управлять"
3. **Ожидаемый результат**:
   - Открывается диалог назначения площадок
   - Можно назначить/отменить площадки
   - Работает так же, как для других ролей

### 5. Проверка в базе данных
Выполнить SQL запрос:
```sql
SELECT 
    id, 
    first_name, 
    last_name, 
    role, 
    company_id, 
    assigned_site_ids
FROM user_profiles
WHERE company_id = '00000000-0000-0000-0000-000000000001'
ORDER BY role, first_name;
```

**Ожидаемый результат**:
- Роли сотрудников соответствуют тем, что назначены в UI
- `assigned_site_ids` корректно обновляются

## Проверка ограничений безопасности

1. Проверить, что в диалоге изменения роли НЕТ опций:
   - ❌ Администратор
   - ❌ Супер-админ
2. **Ожидаемый результат**: Эти роли недоступны для выбора

### Тест 5: Проверка изоляции компаний
1. Войти как ответственное лицо компании A
2. Попробовать изменить роль сотрудника компании B (через API)
3. **Ожидаемый результат**: 
   - Ошибка "Вы можете изменять роли только сотрудников своей компании"

## Критерии успешного теста

✅ **Пройден**, если:
1. Роли изменяются мгновенно без перезагрузки страницы
2. Цвета аватаров соответствуют ролям
3. Изменения сохраняются в базе данных
4. Кеш пользователя автоматически обновляется
5. Нельзя назначить роли администратора
6. Нельзя изменить роли сотрудников других компаний
7. Все три роли (Менеджер, Оператор, Инженер) работают корректно

## Возможные проблемы

### Проблема 1: "Пользователь не найден"
**Решение**: Проверить, что в базе данных есть пользователи с `company_id` = ID компании ответственного лица

### Проблема 2: Роль не изменяется
**Решение**: 
1. Проверить логи в консоли
2. Убедиться, что RLS функции `disable_rls_for_update` и `enable_rls_after_update` существуют
3. Проверить RLS политики для таблицы `user_profiles`

### Проблема 3: Ошибка "Только администраторы..."
**Решение**: Убедиться, что у пользователя роль `companyResponsible` в базе данных
